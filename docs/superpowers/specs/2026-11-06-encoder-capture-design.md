# Encoder capture diagnostic v0.2

The coordinator confirmed that fast hand rotation produces frozen/inconsistent counts while careful slow rotation produces steady counts. Both IR sensors and physical encoder channel routing have passed their basic user-run checks. The v0.1 task requests a 1 ms delay but normally samples at approximately 20 ms under the port's 10 ms tick. This change removes that acquisition dependency; it does not claim a measured maximum edge rate.

Use one application-owned IO_BANK0 handler through tk_def_int, on processor 1/core 0, for both edges of GP4/5 and GP16/17. The current radio port polls GPIO and its optional SDK interrupt functions are weak no-op stubs, so do not use gpio_set_irq_enabled_with_callback. GPIO IRQ capture uses no PIO resources; PIO remains an alternative if measured interrupt latency is inadequate. Reducing the kernel tick would still leave acquisition dependent on task scheduling and is not selected.

Keep all code in the Motion application module, with a portable capture service and a small RP2040/kernel backend. Do not modify the shared kernel, BSP, radio stack, pin mapping, IR path or motor no-drive policy. Continue the existing aai05/bring-up checkout and preserve the pending evidence/document corrections.

Initialize capture in the processor-1-affined Motion task. Refuse initialization when any GPIO event owner is enabled or forced on either core: tk_def_int uses a globally shared vector table in this port. A future GPIO user must join the common dispatcher explicitly. Interrupt priority is 2 (external IRQ priority, separate from task priorities). Motion remains task priority 12; it only publishes snapshots after acquisition moves to the handler.

The handler masks status to owned edge bits, acknowledges only those bits, and samples both A/B inputs of each affected wheel together. A batch containing multiple latched edges for one wheel cannot establish edge order: increment a saturating per-wheel overrun counter, resynchronise A/B, and do not guess movement. Retain the existing diagonal-transition rejection and saturating signed counts. Track a saturating total handled-IRQ counter. Copy capture state under interrupt-preserving SMP spinlocks; never print, allocate, block, or use the snapshot mutex inside the handler.

Reporting adds ENC_READY, capture error, IRQ count and per-wheel overrun counts; DRIVE=OFF remains explicit. A snapshot's age describes snapshot publication, not the time of the last wheel edge. Initialization failure is visible and never enables motor drive. The image/banner is v0.2; preserve v0.1 artifacts and logs. Use distinct dated build logs and real UF2 hashes.

Acceptance before delivery: host decoder, motor-startup and capture tests pass with strict warnings and sanitizers; TEST=0 and TEST=1 compile/link with Wi-Fi driver active. Host capture tests deliver many edges between task reads, exercise both wheels/directions, unrelated pending events, coalesced edges and invalid transitions. Board acceptance remains pending: no unintended motion, stable stationary counts, each wheel counted independently at slow and faster hand speeds, and no growth in bad/over during an accepted trial. Zero errors alone does not establish the maximum reliable rate or calibrated distance.
