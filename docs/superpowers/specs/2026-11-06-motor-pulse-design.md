# Raised-wheel motor pulse test v0.3

The coordinator disconnected the car and authorized development of the next motor test. Basic IR and v0.2 manual encoder response are user-confirmed; do not repeat them. Motor polarity, powered feedback, power stability and counts/revolution remain unverified.

Use onboard active-low GP20 for one explicit NEXT press and GP21 for a latched software STOP. USB CDC RX is discarded in this port, so serial commands would require a shared USB service change; avoid that. An automatic boot sequence is rejected because the coordinator should control each activation. Preserve the existing three modules and current aai05/bring-up checkout.

Each fresh GP20 press requests exactly one pulse in this order: M1 direction 1, M1 direction 2, M2 direction 1, M2 direction 2. Directions describe electrical polarity, not physical forward. Duty is fixed at 25%, duration 400 ms, one wheel only. After each pulse wait at least 1000 ms and require a fresh press; after four pulses DONE requires reset. A held button at startup never starts motion. Debounce NEXT for 40 ms; STOP is acted on at the first Motion sample and remains latched until reset. Capture/driver failure or any encoder invalid/overrun/saturation indication also latches STOP. No automatic duty increase if a motor fails to turn.

Use PWM slices 4/5 on GP8..11 at configured 10 kHz (125 MHz system clock, divider 1, period 12500). Cytron's board truth table is 00 brake, 10/01 opposite drive polarities, 11 coast. Keep the constant leg high and modulate the other leg low for 25% of each cycle, so inactive cycles coast. Force both GPIO outputs high while switching muxes and release the constant leg first. On stop preload SIO high, return all four pins to SIO coast, then disable owned PWM slices.

Reserve RP2040 timer alarm0/IRQ0 at external priority 1, core 0, for an independent one-shot cutoff. The current kernel uses SysTick and USE_PTMR=0. Refuse an already armed/enabled/forced alarm0 or enabled PWM4/5; do not change kernel/BSP/radio code. Arm the timer before enabling drive; detect a missed/past deadline before releasing coast overrides and stop. The timer handler and Motion calls share an interrupt-preserving SMP lock; the driver is the sole runtime motor writer. Report active/wheel/polarity/duty, last pulse elapsed microseconds, cutoff count, controller phase/step and faults. The hardware-counter elapsed value is a software observation, not an oscilloscope WCET measurement. IRQ masking/hardware faults remain outside a hard real-time guarantee. Motion latches a driver fault and stops if the pulse is still active after 500 ms; this fallback leaves a 100 ms margin so the coarse task clock does not preempt the normal 400 ms hardware cutoff.

Cold-boot dependencies are explicit: the priority-1 initial task establishes/validates the watchdog-derived 1 MHz timer tick before yielding to the core-0 USB/radio services. An incompatible nonzero divider, paused/reset timer, wrong reference clock or active watchdog needing retiming is rejected. The shared timer counter is never reset. Pulse initialization separately deasserts only PWM reset and requires RESET_DONE within a bounded poll. This is application peripheral initialization; shared kernel/BSP/radio sources remain unchanged.

Retain encoder IRQ13 and IR reporting. Use monotonic kernel operating time for application ages/control deadlines. Snapshot publication and console output occur only after motor/button handling and never while the pulse lock is held. Version/banner and filenames must clearly identify v0.3 as motion-enabled, idle until a button press. Preserve all older images/evidence. Initial board test uses raised wheels and laptop USB as the single source, consistent with Cytron's documented USB power option; no combined-load rating is inferred. A reset/no movement is a result to investigate, not permission to increase duty or hold the motor stalled.

Acceptance for software delivery: portable controller tests for explicit starts, held/bouncing NEXT, STOP precedence/latch, cooldown, all four steps, dependency faults and timestamp wrap; actual driver register-boundary tests for polarity/coast transitions, limits, timer cutoff independent of task execution, conflicts and initialization failure; all previous host tests plus normal/TEST builds with Wi-Fi driver active. Fresh review required. On-board motion and actual pulse timing remain pending coordinator logs.

References: supplied Robo Pico Board Datasheet, Cytron motor/button examples at https://github.com/CytronTechnologies/Cytron-ROBO-PICO and board power description https://www.cytron.io/p-robo-pico. GPIO truth-table values are board-level and do not identify the unverified motor model/rating.
